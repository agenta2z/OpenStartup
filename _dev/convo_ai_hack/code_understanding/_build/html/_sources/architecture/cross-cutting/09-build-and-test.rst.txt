.. _build-system:

============================
Build System & Testing
============================

**Build:** Gradle 8.x with Kotlin DSL (``build.gradle.kts``).
**Modules:** 86 gradle subprojects in 5 tiers.
**Java:** 21 (per AGENTS.md and verified ``.sdkmanrc``).

Build-rule enforcement
=======================

Gradle build scripts include **dependency-resolution constraints** that throw ``GradleException`` on rule violations:

- platform must not depend on product or aifeature
- foundation must not depend on platform/product/service
- no module depends on another's ``-impl``
- ``-spi`` only consumed by matching ``-impl`` and ``convo-ai-service``
- foundation tests must use MockK (not Mockito/Spock/etc.)

Per AGENTS.md line 24: "Mockito, PowerMock, EasyMock, Spock are forbidden at dependency resolution time" — verified empirically by attempting to add a Mockito dep and observing the build fail.

Coverage tiers (Kover) :sup:`(per AGENTS.md)`
==============================================

Different tiers have different minimum line-coverage thresholds:

.. list-table::
   :header-rows: 1
   :widths: 60 20 20

   * - Module pattern
     - Min line coverage
     - Min branch coverage
   * - ``convo-ai-foundation-*-impl``
     - 80%
     - (tier-default)
   * - ``convo-ai-platform-*-impl``
     - 70%
     - (tier-default)
   * - All other ``-impl``
     - 60%
     - (tier-default)
   * - ``-api`` and ``-spi``
     - (no requirement)
     - (no requirement)

The bar for foundation is highest because foundation bugs have universal blast radius.

Lint stack
===========

- **detekt** (Kotlin static analysis) — config at ``detekt.yml`` + custom rules at ``detekt-rules-custom/``
- **ktlint** (Kotlin formatter) — runs as part of detekt
- **Spotless** — secondary formatter / formatter-of-formatters

Per AGENTS.md: ``./gradlew detekt`` is the canonical lint command.

Test types
===========

The codebase distinguishes:

.. list-table::
   :header-rows: 1
   :widths: 25 30 45

   * - Type
     - Task
     - Purpose
   * - **Unit tests**
     - ``./gradlew test``
     - Fast, mocked, runs per-module
   * - **Architecture tests**
     - ``./gradlew :modules:service:testing:arch:test``
     - ArchUnit assertions on tier rules
   * - **Startup test**
     - ``./gradlew :convo-ai-test-integration:startupTest -Pnebulae.enabled=true``
     - Smoke: full Spring context loads
   * - **Integration tests**
     - ``./gradlew :convo-ai-test-integration:integrationTest``
     - Full controller/handler tests against mocked sandbox
   * - **Sharded integration (CI)**
     - ``./gradlew :convo-ai-test-integration:integrationTestShard{1,2,3}{FlagsOn,FlagsOff}``
     - 6 parallel shards CI runs (each ~5-10 min)

The local-vs-CI mismatch :sup:`(observed empirically)`
========================================================

Per ``hack_states/02-integrationTest-result.md`` and ``hack_states/03-failure-classification.md``:

- The non-sharded ``integrationTest`` task **fails locally** with 37/1445 failures (87.3% pass rate)
- CI does NOT run the non-sharded task; CI runs 6 sharded variants WITH feature-flag context
- 21 of 37 local failures concentrate in test classes that depend on specific feature-flag states absent from local sandbox

**Practical implication:** for local development, prefer ``startupTest`` for daily validation; reserve full ``integrationTest`` for explicit "before-PR" runs and accept some failure noise.

Sandbox: ``atlas nebulae start -s integration-tests``
======================================================

The integration test environment runs in a local Docker Compose sandbox managed by ``atlas nebulae`` (Atlassian's local-dev sandbox tool).

Containers (verified at runtime):
- microservice (the convoai service itself)
- 12+ wiremock-backed sidecars: TCS, TAP, Ranger, Statsig, ASAP, IdentityService, ProvisioningService, AI Gateway, etc.
- 2 Redis clusters (provisioning, async-tasks)
- 1 PostgreSQL (Kamino backing)
- Egress proxy
- Statsd

Total: ~24 containers. First start takes ~5-10 minutes (multi-GB image downloads). Subsequent starts: ~30-60 seconds.

Per ``hack_states/01-startupTest-result.md``: a verified-working startup-test wall time is **1m 7s** (after the sandbox is up).

What you would change here
===========================

- **Add a new gradle module** → create new directory under modules/<tier>/ + ``build.gradle.kts`` + register in ``settings.gradle.kts``
- **Loosen a coverage threshold** → modify the relevant ``buildSrc`` Kover config
- **Add a new lint rule** → custom rule in ``detekt-rules-custom/``

What you would NOT change here
===============================

- The api/impl/spi rules (architectural; changing them has cascading impact)
- The Mockk-only rule for foundation (philosophical; team-agreed)
