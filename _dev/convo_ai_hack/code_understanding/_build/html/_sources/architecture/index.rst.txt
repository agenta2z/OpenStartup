How to read this documentation
===============================

This is a **structured reference** — not a tutorial. Read in this order if new to the codebase:

1. :ref:`arch-overview` — the 5-tier hexagonal architecture, build rules, mental model
2. :ref:`request-lifecycle` — trace one specific endpoint (chat streaming) end-to-end
3. **One tier deep-dive** — pick whichever you'll work in (e.g. :ref:`product-tier` if adding a feature)
4. **Cross-cutting concerns** — read the ones relevant to your task
5. :ref:`module-catalog` — reference when looking up unfamiliar modules

What this documentation IS
===========================

- **Grounded:** every Critical/High claim cites file:line; tier-overview claims cite directories or AGENTS.md
- **Honest about scope:** ``:sup:`(verified)``` / ``:sup:`(inferred)``` / ``:sup:`(agent-reported)``` markers
- **Discoverable:** module catalog so unfamiliar modules can be looked up

What this documentation IS NOT
================================

- **Not a class diagram.** Diagrams of 12,990 source files would be noise.
- **Not exhaustive.** Per-method docs aren't here — that's KDoc territory.
- **Not a security audit.** Patterns are described as observed, not validated as sufficient.
- **Not a tutorial.** No "build a hello-world agent" walkthrough.
