## 9. Root causes (sorted by leverage)

### RC-1: Workspace whitelist excludes `_runtime/tasks/**` (highest leverage)

Every inferencer that crosses task boundaries hits `open_files: Path is outside both the workspace directory and whitelisted paths`. Aggregators (3 of them) recovered via `bash cat`; worker_1's fix step did not. This single sandbox configuration mismatch is the root cause of:
- Issue #1 (hallucinated CVE labels — fix couldn't read prior artifact)
- Most of finding #5 (silent capability degradation forcing bash workarounds)
- Wasted subagent iterations across many stages

### RC-2: Fix-step prompt does not enforce "must read prior artifact"

The fix prompt says "YOU MUST copy the prior version artifact and apply targeted edits" but provides no fallback instruction when the tool fails. The aggregator-side prompt has implicitly conditioned the agent to fall back to bash; the fix-side prompt has not. Worker_1's fix step exemplified what happens when only the summary is present and the tool fails.

### RC-3: Reviewer's `<ArtifactUnderReview>` is a SUMMARY, not the artifact

Embedding a `<Response>` summary instead of the full artifact relies entirely on the reviewer's discretion to read the file path. This works for the strong models used in this run, but is fragile: a weaker model would review the summary only.

### RC-4: "Update docs" is a plan-producing prompt, not an executing prompt

Worker_1's subtask says "Update `architecture/cross-cutting/01-business-and-technical-goals.rst` with: …" — but the prompt template encourages writing a markdown deliverable to `output.md`, not editing RST files in place. There's no verifiable post-condition (e.g., "after success, `git diff architecture/cross-cutting/` must be non-empty"). So the LLM produced a plan instead.

### RC-5: MultiFlow's "different perspectives" is not enforced

flow_0 and flow_1 prompts are byte-identical except for the output path. No system-prompt diversity, no temperature variation, no perspective override. The aggregator prompt's claim of "two independent perspectives" is aspirational rather than enforced.

### RC-6: Reviewer rubric not enforced

Worker_0's reviewer set `approve: true` while raising 1 MAJOR + 6 MINOR + 1 COSMETIC issues, violating the rubric ("approve only on trivial COSMETIC issues"). The dual-review safety net was effectively bypassed.

## 10. Remediation recommendations (prioritized)

### P0 — Immediate (fixes Issue #1 and most of finding #5)

1. **Add `_runtime/tasks/**` to the RovoDev workspace whitelist.** This is the single root cause of the worst defect in this run.
2. **Harden fix-step prompts** to explicitly say: "If `open_files` fails on the prior artifact path, you MUST use `bash cat` to read it. Do NOT reconstruct from the summary alone."
3. **Inline the prior artifact content in fix prompts as a fallback** (the prompt already inlines reviewer feedback; doing the same for the prior artifact removes the tool-read dependency entirely).

### P1 — Near-term (correctness improvements)

4. **Reviewer prompts should embed the full artifact** (not a summary), or require a verifiable "I read the file" tool-call check before accepting the verdict.
5. **For "update X file" subtasks, add a verifiable post-condition** — e.g., a post-execution check that `git diff <expected-path>` is non-empty. Make file edits a first-class outcome separate from "deliverable artifact written".
6. **Tighten the reviewer rubric enforcement**: `approve: true` should be impossible if any issue has `severity != COSMETIC`. Add a structural validator on the JSON response.

### P2 — System health

7. **Seed MultiFlow flows with distinct perspectives** — different system prompts, temperatures, or persona overrides — so diversity is real, not aspirational.
8. **Fix line-number reporting**: investigate why outputs are systemically +1 off. Likely an off-by-one in how `open_files` or `expand_code_chunks` reports line numbers vs how the agent re-cites them.
9. **Add tool-result validation** for the Atlassian MCP `https://https://...` double-prefix artifact.
10. **Clean up empty `flow_*/round01/` directories** — either run the per-flow review/fix or stop pre-creating empty shells.

### P3 — Efficiency

11. **Reduce redundant cross-layer verification.** Currently flow, aggregator, and review all independently re-verify the same upstream claims. Consider passing a verification manifest forward.
12. **Tune subagent iteration budgets** for flow agents to reduce "iteration limit reached" log noise.
