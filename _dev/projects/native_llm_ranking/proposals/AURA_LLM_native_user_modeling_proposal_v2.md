## 0. Executive summary

- **The paradigm is settled; the aim is the decision.** LLM‑native ranking converges on a **unified, typed token space** (behavioral + semantic + soft context tokens in one transformer). The load‑bearing empirical claim (LLaTTE, verified): *"semantic features bend the scaling curve — a prerequisite for scaling."* This is the **what**. The **where** and the **how** are the strategic choices — and they, not the mechanism, are where the differentiation must live.
- **Correction that reshapes the bet: the *injection mechanism* is NOT the white space.** A fifth verification pass established (primary sources, §1.2/§8) that injecting non‑behavioral signals as soft tokens into an *organic* ranking transformer is **already actively worked across MRS**: **Multitoken NRO** and **RankFM‑2 multi‑token cross‑attention** (dense/sparse/embeddings → HSTU FM, for Expert transfer), **CoTrain (CoT)** (InterestFM/UME **content** embeddings injected into HSTU positions with **ATTENTION_NRO / full‑cross‑interaction** strategies), **EMUIC**, **CUET**, **FM RankMixer**, **HSTU‑CInt**, and shallow **Interest Encoder** gating (~0.08). v1/early‑v2 framed "deep soft‑token injection into organic ranking" as genuine white space; **that is now refuted.** The proposal is corrected accordingly.
- **Where the differentiation actually lives — four opportunities (new §4).** Not *whether* to inject tokens, but **what goes in, how it's optimized, and what structure it preserves**:
  - **(A) Ranking‑aware content‑embedding optimization** *(gap supported; #1 for ads).* SAGE/AdsLlama embeddings are **frozen, pre‑computed, thrown over the wall** — trained on their own objectives, no ranking→encoder gradient. Close the loop with a lightweight adapter (LoRA/bottleneck) + EMA + offline distillation‑to‑cache. Portfolio effect across every SAGE consumer. The team **owns both sides** (SAGE + ads ranking).
  - **(B) Cross‑domain facet‑preserving multi‑tokens** *(gap confirmed; #1 for mission).* RankFM hands **2×512 pooled** vectors to Experts; CMSL **already builds K interest‑facet sub‑sequences** then **pools them to `CMSL_USER_EMBEDDING_{0..3}` (4×128) + PMA** before export. Stop pooling the structure away; export facets as multi‑tokens injected into other surfaces' Experts.
  - **(C) Ranking/engagement‑aware tokenizer objective** *(partial gap; #3).* Tokenizers are reconstruction/content‑only; the documented **"engagement alignment gap"** means similar‑looking items get similar codes despite different engagement. Add an engagement‑discrimination term. This is Meta's own stated Phase‑3 target.
  - **(D) Adaptive per‑item token budget** *(gap confirmed; #4).* Production budgets are **fixed** (4‑token SIDs; fixed‑N soft tokens); spend tokens where information need is highest. (Direction is contested — RASTP vs Matryoshka — so it's a research axis, not a settled recipe.)
- **The flagship mechanism (from CA‑MSL): the Multimodal Token Maker** — the *vehicle*, not the novelty. A lightweight projector maps rich embeddings (SAGE/AdsLlama content, RankGraph, user state) into **N continuous soft tokens in d_model**, deeply cross‑attended in the ranking sequence transformer. Two‑stage serving (heavy content pre‑computed/cached; tiny online Token‑Maker MLP) keeps it within latency budget. Because the vehicle is crowded, we **build on and contribute into** the existing organic vehicles (CoTrain / RankFM‑2 multi‑token XA / HSTU‑CInt) rather than claim a parallel "first."
- **Two‑pronged path.** **Prong A (fast validation, owned assets):** ads‑**CMSL** — the team owns both the content source (SAGE/AdsLlama) *and* the sequence consumer (CMSL); the gap is the *connection* and its *quality* (Opp A). **Prong B (differentiated claim, verified gaps):** **organic RankFM Expert** — carry **Opps A+B+C** into organic ranking (via CoTrain / RankFM‑2 injection slots), where the *facet‑preserving cross‑domain token* (B) is a confirmed production gap. Consistent with AURA's charter ("starting with ads"; mission = **bridge organic ↔ ads**).
- **Hybrid tokenization (resolves the quantization bottleneck).** **Continuous soft tokens** for deep discriminative‑ranking fusion (preserves information; SID‑based GR saturates), **discrete semantic IDs** for generative retrieval / cold‑start / cardinality‑limited features. Not continuous‑only (CA‑MSL over‑rotated), not SID‑only (v1 over‑rotated).
- **The two hard truths we design around:** (i) **alignment is the #1 problem** — raw/frozen content embeddings *hurt* rankers unless aligned to the collaborative/ID space (this is the mechanism that makes Opp A pay off); (ii) **the inference gap is the gating blocker** (Meta's ST LLM north star) — serving budget is a day‑one constraint (and the motivation for Opp D). Framing throughout: **LLM + CF, not LLM replacing CF.**
- **Path:** P0 fail‑fast offline (content Token Maker + **Opp A adapter** → deep fusion in ads‑CMSL, single model) → P1 flagship (Multimodal Token Makers + deep cross‑attention on ads‑CMSL **and** organic RankFM/CoTrain; **Opps A+B**; hybrid tokenization; alignment stage) → P2 generative user FM + User Token Maker (**Opp B** facet export) + **Opp C** tokenizer → P3 LLM‑native generative proxy, with **Opp D** adaptive budget as a cross‑cutting serving axis. Gated by MC / the 0.05% NE bar → GAS, and evolved by **RankEvolve**.

## 1. Context & the strategic correction (what changed from v1, and again in this pass)

### 1.1 Where AURA is (the LLM‑inspired baseline) — Existing
AURA (Hong Li's team's *User Intelligence Engine* — "Adaptive User Representation & Reasoning Architecture") today produces user embeddings from behavioral towers (WHEN/UniArch, `//aps_models/exploration/aura_model`), aggregates them, and injects 16 `AURA_USER_EMBEDDING_*` F3 features into ads ranking (CMF/DPA/IG). Its stated problem is **siloed** user understanding (organic vs ads), and its named 26H1 ambitions include **Tower UM with data enrichment (AdsLlama semantic IDs, graph tokens, organic data)**, **Generative UM**, and **LLM‑native UM**, with three consumption modes: **embeddings, a distilled small model, and an "LLM‑native consumption proxy."** This is **Paradigm‑1‑ish** user modeling consumed as embeddings. (Verified: pipeline live but early — features deployed ~Apr 2026; H1 footprint is enablement/exploration, not a shipped topline win.)

### 1.2 The verified landscape — Existing (checked against primary sources)
- **Ads unified‑modality is crowded/in‑production:** **UNITY / Fully Tokenized Model (FTM)** (Tokenization Co‑Design; O(10K) features → a 3D LLM‑like tensor via RQ‑VAE discrete Semantic IDs; ~80% model‑size reduction, +0.13%/+0.02%/+0.06% NE, ~15% QPS; ~70% of features tokenizable today). **LLaTTE** (two‑stage user model; +4.3% conversion FB Feed/Reels; part of COFFEE). **CU Embeddings Unification / SAGE (formerly AdsLlama; v3.0 = Qwen3‑VL‑2B)** = the semantic‑ID supply chain ("unify entities of heterogeneous format/domain into a single unified semantic‑ID space"; owner **Hong Li, MRS Platform – Algorithms**).
- **Generative retrieval is crowded:** **GRADIENT** (Ads GR; RQ‑VAE; constrained decode; ~10× FLOPs reduction; +1.2% offline recall; ~Q2 2026), **InstaBrain** (IG GR; Llama‑3.2‑1B generates SIDs).
- **Organic ranking is behavioral‑first — but *content/soft‑token injection is already actively worked* (the correction).** Per‑surface **HSTU** (FB Feed IFR, FB Reels UDD, IG ESR) + **HSTU‑CInt** (prepends contextual tokens — user‑level features, cross‑surface embeddings incl. POLARIS FM & CMSL cross‑surface embeddings — into the UIH; deep L1 self‑attention; the backbone for CMSL, all organic LSR, and RankFM). And, critically:

  - **RankFM‑2** (FM/Expert paradigm) still lists **multimodal content understanding as a *future* FM capability** — but "content embeddings into HSTU with cross‑attention" per se is **not** future; it is being built (above).

Our content path is honestly **"2c supply (cached SAGE) + 2b fusion (deep cross‑attention)"** — and **Opp A is the move from 2c‑frozen toward end‑to‑end.** The production trajectory is **layered, not a replacement** (Layer 1 behavioral HSTU + Layer 2 offline content + Layer 3 soft/discrete tokens + Layer 4 LLM reasoning) — reinforcing **augment, not replace**.

## 2. Design principles (v2)

1. **Unified, typed token space (Paradigm 2b + 2a).** Every event → typed tokens: behavioral IDs + **hybrid** semantic (discrete SID *or* continuous soft token) + typed user/context soft tokens, in one d_model space.
2. **Hybrid representation.** Continuous soft tokens for **deep discriminative‑ranking fusion** (info‑preserving; SID‑based GR saturates); discrete SIDs for **generative retrieval / cold‑start / cardinality**. Decision table in §3.2.
3. **Differentiate on WHAT/HOW/STRUCTURE, not the mechanism.** The injection mechanism is commodity at Meta now; the edge is (A) ranking‑aware source embeddings, (B) preserved cross‑domain structure, (C) ranking‑aware tokenizer objective, (D) adaptive budget (§4). Deep cross‑attention (vs shallow ~0.08 gating) is table stakes, not the claim.
4. **Collaborative‑first; semantics as scaling fuel.** LLM + CF, not replace. Behavioral dominates; semantics unlock scaling + cold‑start + cross‑surface transfer. Layered stacking, not replacement.
5. **Close the loop to the source (Opp A) — alignment is the mechanism.** Don't consume content embeddings frozen; make them ranking‑aware via a lightweight adapter co‑trained with ranking loss, aligned to the collaborative/ID space (QARM/IDProxy/DAS lesson), stabilized for other consumers via EMA / offline distillation‑to‑cache. Keep code‑IDs / soft tokens trainable end‑to‑end.
6. **Match objective to use case.** Discriminative ranking (co‑trained) for the ranking path; dual **causal + masked** for the embedding/generative‑proxy modes; contrastive alignment throughout; **engagement‑discrimination** in the tokenizer (Opp C).
7. **Co‑train with ranking; decouple heterogeneous tasks** (typed Token Makers, MoE/task‑aware tokens, gradient detachment) to avoid the seesaw / negative transfer.
8. **Privacy‑native.** Opt‑out via **cohort_id**; self‑supervised; cross‑funnel per the Event‑Sequence North Star.
9. **Serve within budget (day one).** Two‑stage (cached heavy content + tiny online Token Maker) + Adaptive Ranking Model / M‑FALCON / distillation / RLS; **adaptive token budget (Opp D)** as an efficiency lever.
10. **Build on owned assets; contribute into existing vehicles; evolve autonomously.** The team owns SAGE/AdsLlama + CMSL + Ads Graph Learning; build the *connection and its quality*, contribute A/B/C into CoTrain/RankFM‑2/RankID, reuse RankID/G2Rec/CU‑Unification; evolve tokenizer/arch/objective/fusion with **RankEvolve**.

## 3. The core mechanism — Multimodal Token Makers (the *vehicle*)

### 3.1 Typed Token Makers (from CA‑MSL, generalized) — Proposed
A **Token Maker** is a lightweight projector that maps a rich embedding into **N continuous soft tokens in d_model**, so the ranking transformer attends over them jointly with behavioral tokens:

```python
class TokenMaker(nn.Module):
    """Project a rich signal embedding -> N soft tokens in d_model (typed per signal)."""
    def __init__(self, input_dim, d_model, n_tokens):
        self.proj = nn.Sequential(
            nn.Linear(input_dim, d_model * n_tokens),
            nn.SiLU(),                                  # match HSTU activation
            nn.Linear(d_model * n_tokens, d_model * n_tokens),
        ); self.n_tokens, self.d_model = n_tokens, d_model
    def forward(self, emb):                              # emb: [B, input_dim]
        return self.proj(emb).view(-1, self.n_tokens, self.d_model)  # [B, N, d_model]
```
- **Typed makers per signal:** ContentTokenMaker (SAGE/AdsLlama content, or InterestFM for organic — Knowledge‑owned), GraphTokenMaker (RankGraph / Ads Graph Learning), UserTokenMaker (§3.3). Typing keeps signals separable and mitigates negative transfer.
- **Token budget (serving‑aware):** ~2–4 soft tokens per entity; e.g. 200 items × 4 = 800 extra tokens, within HSTU's 2K–16K window (Expert uses ~2K). Budget itself becomes **adaptive** under Opp D (§4.2‑D).
- **Deep cross‑attention & placement:** the maker's tokens enter the sequence and are attended at every layer against the target. **Placement matters** — RankFM‑2 found **prepend ≫ append** for injected tokens (append lost +0.22% NE); prepend/interleave, don't append. This is the difference from Interest Encoder's pooled ~0.08 gating — but note it is *not itself novel* (CoTrain's ATTENTION_NRO and RankFM‑2's multi‑token XA already do deep cross‑attention); the novelty is what fills the tokens (§4).

### 3.2 Hybrid tokenization + a ranking‑aware objective (Opp C) — Proposed

| Use case | Representation | Why |
|---|---|---|
| **Deep discriminative ranking fusion** | **Continuous soft tokens** (Token Maker) | Preserves information; SID‑based GR saturates (quantization bottleneck); best for CTR/CVR reasoning |
| **Generative retrieval / cold‑start / cardinality‑limited features** | **Discrete Semantic IDs** (RQ‑VAE/RQ‑KMeans via RankID; consider RQ‑FSQ) | Compact, generateable, cold‑start‑friendly, downstream‑admissible; RQ‑FSQ matched dense AUC at ~280× storage, +1.522% for near‑zero‑ad‑history users |
| **Lifetime long‑history compression** | **Virtual tokens** (ViSTA‑style) | Condense 12K+ items into a compact user state within cost |

- **Config:** codebook near the **~3×256 sweet spot** (or multi‑res `[4096,2048,1024]`); k‑means init (top collapse mitigation); track token **entropy** (r≈0.73 with NE) and **utilization** (r≈0.64).
- **Ranking/engagement‑aware objective (Opp C) — Proposed.** Standard RQ‑VAE trains for **reconstruction**, which is **content‑only**; the internal Semantic‑ID survey documents the resulting **"engagement alignment gap": *"items that are semantically similar in content may not be interchangeable from an engagement perspective."*** Add an engagement‑discrimination term so engaged vs skipped items get different codes:  `Loss = α·Reconstruction + β·EngagementDiscrimination(contrastive) + γ·Commitment`. Place the contrastive term at the **codebook‑embedding level** (works — SealNet/RankID‑Graph) not the **decoder‑output level** (conflicts with reconstruction). This is directionally validated internally (SealNet/RankID‑Graph codebook contrastive; `CoEngagementAlignmentLoss` in Unified Ads+Products SemID; GRADIENT concatenates discriminative TTSN ad‑tower embeddings — 256d content + 128d TTSN → 384d — into the tokenizer input) and is **Meta's own stated Phase‑3 target** (Phase 1 = separate tokenizer + engagement features today → Phase 3 = full end‑to‑end tokenizer↔ranking co‑training). *Honest caveats:* GRADIENT's documented motivation for TTSN is **auction/paced‑bid bias correction**, not literally "engagement interchangeability" (our engagement framing is a reasonable extrapolation); a **pure** joint reconstruction+ranking objective is still mostly academic (EGA, ETEGRec, TRM). So Opp C is a **partial** gap and an active frontier — position AURA‑Native's tokenizer as **contributing to Meta's Phase‑3 target with RankID**, not as first‑mover.

### 3.3 The User Token Maker + cross‑domain facet export (Opp B) — Proposed
AURA is a *user* platform, so its differentiated maker is the **User Token Maker**: convert the full user state — behavioral history + **G2Rec soft interest prototypes** (build on; G2Rec is MRS/Max Fan's soft‑assignment interest tokens) + Biography profile + graph + context — into a compact set of **rich user soft tokens** the ranking transformer deeply attends to.

**The differentiated core (Opp B — verified gap): preserve cross‑domain *structure*, don't pool it away.** Today, cross‑domain knowledge is **compressed to a pooled vector at the surface boundary**: RankFM hands Experts **"2 embeddings × dim 512"** (verbatim, MRS Science Book Ch.05 — "the handoff to the Expert"); **CMSL already constructs K semantically‑coherent interest‑facet sub‑sequences** ("each captures a distinct facet of user interest") but then **pools them to `CMSL_USER_EMBEDDING_{0..3}` (4×128) + PMA fixed‑size** before export to 5+ ads heads. So the facet structure the team's *own* model builds is **thrown away at the boundary.** Opp B is therefore not "build something new" — it is **"stop pooling CMSL's facets; export them as K×M multi‑tokens"** injected into other surfaces' Expert models:

```
User behavior on Surface A (e.g., IG Reels)
   → CMSL builds K coherent facet sub-sequences  (EXISTS today, then pooled away)
   → each facet → UserTokenMaker → M soft tokens  (PROPOSED: keep the structure)
   → K×M cross-domain tokens injected (prepend/interleave) into Surface B's Expert
   → e.g. {coarse: cooking} {fine: Italian} {format: short tutorials} {temporal: evenings}
```
This is a **confirmed production gap** (nobody exports facet‑preserving cross‑domain multi‑tokens into other surfaces' rankers). *Adjacent, not the same:* **MUI‑TTSN** (Threads) splits a user tower into 20×128 segments and has an X‑surface module, but it is **within‑surface** two‑tower retrieval, not cross‑surface Expert injection; external analogs (Snap **UUM**, Meituan **SIF**, Tencent **RankUp**) validate the direction but are not Meta production. *Honest attribution:* RankFM's **+0.163% Cap30 ("highest‑impact ranking launch in 3 years")** proves the **FM/Expert cross‑surface paradigm + scale** is enormously valuable (measured on FB Video UDD) — it is **not** an isolated ablation of "cross‑domain signal," so cite it as motivation for the paradigm, not as proof that de‑pooling alone yields +0.163%.

### 3.4 Two‑stage serving + ranking‑aware source (Opp A) — Proposed
Heavy content/user understanding runs **offline/nearline and is cached** (the SAGE/AdsLlama Inference Cache is real: ~46% hit over ~137M requests; SAGE serves ~200–1k QPS for ads, ~5k–20k for products). The **only new online component is the tiny Token‑Maker MLP** (<1M params) projecting cached embeddings → soft tokens (~sub‑ms).

**The differentiated core (Opp A — gap supported): make the *source* embedding ranking‑aware, don't just project a frozen one.** Verified: SAGE/AdsLlama embeddings are **pre‑computed offline, served via lookup, trained on their own objectives (self‑contrastive, KD, co‑click/relevance, classification) — with no gradient from any downstream ranking loss** ("thrown over the wall"). Yet **representation/consumption of the *same* information drives large swings**: consuming one CU embedding three ways gave **−0.006% → +0.041% NE**; on CMF, a co‑click vs a relevance AdsLlama variant gave **−0.05% vs +0.07% NE** (opposite signs, same model). Proposed loop‑closure (does **not** break caching):
```
Current:  SAGE → [frozen cached embedding] → TokenMaker → Ranker → loss     (no grad back)
Proposed: SAGE → LoRA/bottleneck adapter → TokenMaker → Ranker → loss       (grad → adapter)
          + EMA / offline distillation of ranking-informed embeddings back into the cache
```
Train **only the adapter + Token Maker** (not all of SAGE — too expensive, degrades general CU); **EMA** keeps the cached embedding stable for the many other consumers; a **distillation variant** improves the cache offline without touching serving. **Portfolio effect:** every model consuming SAGE (AF/AI CMF, DPA, AF IG CTR, PreMatch…) benefits. *Honest caveats:* (i) an internal view holds that **co‑engagement** signals fed back give **diminishing returns** (they already derive from ranking outputs) — so target **content/semantic** ranking‑awareness, not co‑engagement; (ii) the "gap" is inferred from the absence of any adapter+ranking‑loss+EMA into the content encoder plus explicit decoupling rationale, and from adjacent‑but‑different efforts (RecLLM's projector+LoRA on a *frozen* encoder; SOCAE/C‑SQI adapter for *Profile*; the organic UserFM joint‑training *plan*; the tokenization team's "end‑to‑end embedding+tokenization" listed as a *next step*) — it is reasonable, not airtight; (iii) **ownership** — this is cleanest for **ads** (team owns SAGE); the organic analog needs a Knowledge (InterestFM/UME) partnership. This still projects *cached* content (semi‑stale); full **real‑time projection** (fresh, candidate‑dependent) remains a P2+ frontier, gated by latency.

## 4. Where the novelty actually lives, and where to aim

### 4.1 Honest correction: the injection *mechanism* is not the white space
Verification (§1.2, §8) establishes that "inject non‑behavioral / content signals as soft tokens into an organic ranking transformer, with cross‑attention" is **already actively worked** across FM Co‑Design (Multitoken NRO, RankFM‑2 multi‑token XA, HSTU‑CInt), MRS Knowledge (CoTrain content injection, CUET, EMUIC, RankID v3), and adjacent teams (FM RankMixer, Interest Encoder). The **narrowest** slice that no *single* organic effort combines exactly is: *rich content/multimodal → a **few learned** soft tokens (not id‑matched, not shallow‑gated) → deep cross‑attention into RankFM/HSTU **with measured expert transfer**.* That is a **partially‑open** gap at best — too thin to carry the proposal. **So the differentiation is relocated to the four opportunities below**, and Prong B is reframed as **contributing A/B/C into the existing organic vehicles** (CoTrain / RankFM‑2 injection slots / RankID) rather than building a parallel "first."

## 5. Architecture — AURA‑Native (full picture)

- **Inputs:** cross‑surface event sequence (Event‑Sequence North Star: organic 1PD + ads 1PD + offsite 3PD) → per‑event typed tokens: behavioral IDs + **hybrid** semantic (continuous soft token for ranking; discrete SID for retrieval/cold‑start) + typed user/context soft tokens; **cross‑domain facet tokens** (Opp B) from CMSL/RankFM.
- **Backbone:** **RankFM Expert / HSTU‑family / CoTrain** for organic (Prong B), **CMSL** for ads validation (Prong A); long‑context via ViSTA‑style virtual‑token compression; deep cross‑attention over the unified sequence (prepend/interleave, not append).
- **Source quality (Opp A):** LoRA/bottleneck adapter on SAGE (ads) / InterestFM‑via‑Knowledge (organic), co‑trained with ranking loss; EMA + offline distillation‑to‑cache for consumer stability.
- **Tokenizer (Opp C):** RankID SIDs with an engagement‑discrimination term (codebook‑level contrastive).
- **Budget (Opp D):** adaptive per‑item token budget / learned router as a serving‑efficiency axis (research, direction‑contested).
- **Objective:** discriminative ranking (co‑trained) primary; **dual causal + masked** for embedding/generative‑proxy modes; contrastive **alignment** (content↔collaborative). Decouple heterogeneous heads (MoE/task‑aware tokens) to avoid the seesaw.
- **Consumption — AURA's three modes:** (1) **embeddings** (EBF; today's F3 path), (2) **distilled student** (ExFM / on‑policy distillation), (3) **LLM‑native generative proxy** (generative retrieval; ST‑LLM real‑time path).
- **Privacy‑native:** `separable_id` (opt‑in) ∪ `cohort_membership_id` (opt‑out); self‑supervised so unattributed offsite events are usable.
- **Serving (inference gap):** two‑stage (§3.4) + Adaptive Ranking Model (Request‑Oriented Optimization / In‑Kernel Broadcast / selective FP8) + M‑FALCON + KV‑cache + distillation + RLS + adaptive budget (Opp D).
